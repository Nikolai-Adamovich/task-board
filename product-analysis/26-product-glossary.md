# 26 — Product Glossary

Normative terminology. All documents and the implementation must use these terms consistently.

---

| Term                             | Definition                                                                                                                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Tenant**                       | The top-level organizational boundary (a company/team workspace). Isolates all data. Has exactly one Owner.                                                                                                        |
| **Tenant Owner**                 | The single administrative authority of a Tenant; the only role that can transfer ownership.                                                                                                                        |
| **Tenant Admin**                 | Tenant-level administrator delegated by the Owner; tenant-wide authority without per-Project memberships.                                                                                                          |
| **Tenant Member**                | A user with an ACTIVE Tenant Membership; base participation level.                                                                                                                                                 |
| **Project**                      | A work container inside a Tenant; aggregate root owning Tasks, Statuses, Task Types, Labels, Boards, Sprints, Memberships. Has a unique key and default Status/Board.                                              |
| **Project Admin**                | Project-level administrator: members, configuration, sprints, danger zone.                                                                                                                                         |
| **Editor**                       | Project member who can create/edit permitted content (tasks, comments) but not administer.                                                                                                                         |
| **Viewer**                       | Strictly read-only Project member (final decision). Sees everything in scope; can write nothing.                                                                                                                   |
| **Task**                         | The central unit of work (`KEY-n`) inside exactly one Project; always has a Type and a Status; optionally assigned to one Sprint.                                                                                  |
| **Task Type**                    | Project-level classification (initially TASK, BUG, STORY); immutable key, editable name.                                                                                                                           |
| **Status**                       | A workflow state of Tasks, defined per Project; case-insensitive unique name; the Project has one default Status (TODO initially).                                                                                 |
| **Board**                        | A Project-level view configuration consisting of ordered columns; belongs to the Project, never to a Sprint.                                                                                                       |
| **Board Column**                 | An ordered grouping inside a Board that references one or more Statuses. Not a Status itself.                                                                                                                      |
| **Sprint**                       | A timeboxed grouping reference for Tasks within a Project; status FUTURE/ACTIVE/COMPLETED with unrestricted transitions; dates optional with population rules on start/complete.                                   |
| **Backlog**                      | The conceptual set of Tasks with `sprintId = null`. Not an entity.                                                                                                                                                 |
| **Label**                        | A Project-level reusable tag with case-insensitive unique name ("Bug" = "bug" = "BUG").                                                                                                                            |
| **Comment**                      | A Markdown note on a Task with an author identity that survives author deletion via snapshot.                                                                                                                      |
| **Task Relationship**            | A typed link (BLOCKS, RELATES_TO, DUPLICATES) between two Tasks of the same Project.                                                                                                                               |
| **Membership**                   | The access relationship between a User and a Tenant or Project, carrying a role plus an access status. An invited membership persists as ACCESS_REVOKED until the invitation is explicitly accepted (then ACTIVE). |
| **Invitation**                   | The pending-access mechanism embedded in a membership: PENDING / EXPIRED (derived from invitedOn+TTL) / DECLINED / REVOKED; acceptance clears it and activates the membership.                                     |
| **Historical Identity Snapshot** | An immutable display-name copy stored on business records (reporter/assignee/creator/comment-author/audit-actor) so history stays readable and searchable after User deletion.                                     |
| **Archive**                      | Read-only preservation state for a Tenant or Project; reversible; the safe alternative to deletion.                                                                                                                |
| **Delete**                       | Permanent removal. For Tenants/Projects: grace period (DELETION_PENDING) with cancellation first. For Tasks/Sprints/Boards/Labels/Statuses: hard delete with defined cascade semantics.                            |
| **Optimistic Concurrency**       | Mutation protocol where the client sends the last-observed `version`; mismatch yields a structured conflict error instead of silent overwrite.                                                                     |
| **Saved Filter**                 | A named, user-and-project-scoped copy of table query state.                                                                                                                                                        |
| **Mock Checkout**                | The billing placeholder step in first-Tenant onboarding; no real payment data; isolated boundary for future real billing.                                                                                          |
